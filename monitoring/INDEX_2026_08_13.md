**ml_router** (ML-Learned Routing)
- ✅ Chose Balanced tier 85% of the time

- ✅ 2-3x faster than alternatives
- ❌ Lower accuracy (risk of misclassifications)

**always_heavy** (Accuracy Baseline)
- ✅ Highest accuracy, consistent latency
- ❌ Slowest: ~3.5 req/s throughput (bottleneck at scale)
- **Recommendation:** Use only for final validation or when accuracy is paramount

**rule_based** (Human Heuristic)
- ✅ Median latency (838ms) is good
- ❌ Confidence threshold (0.7) too aggressive → 95% escalation → queue buildup → p99 = 4.48s
- **Recommendation:** Lower threshold to 0.5 OR retrain Fast model, then retry

**round_robin** (Naive Load Balancing)
- ✅ No ML logic needed, simple to implement
- ✅ Distributes load evenly
- ❌ Not optimized for actual workload
- **Recommendation:** Acceptable fallback if ml_router fails; not primary choice

## 🔧 Fixes Applied

### Problem 1: Gateway CPU Saturation
**Before:**
```
User Request
   ↓
Gateway (CPU-bound)
   ├─ Load Fast model
   ├─ Run inference on CPU (NO GPU!)
   └─ Feature extraction
   ↓
Balanced/Heavy Services (GPU)
```

**After:**
```
User Request
   ↓
Gateway (stateless orchestrator)
   ├─ Extract features (fast CPU operation)
   └─ Make routing decision
   ↓
Fast/Balanced/Heavy Services (all GPU-accelerated)
```

**Impact:** 
- Eliminated unfair CPU penalty on strategies that choose Fast
- ml_router and rule_based no longer handicapped
- True apples-to-apples comparison

### Problem 2: Histogram Quantization
**Before:** Prometheus default buckets [10ms, 30s] → coarse; all sub-second requests mapped to 10ms

**After:** Custom buckets [10, 25, 50, 75, 100, 150, 200, 300, 500, 750, 1000, 1500, 2000, 3000, 5000]ms
- Fine-grained latency measurement
- Accurate p50/p95/p99 calculations

**Impact:** Meaningful percentile data instead of flat 10.0ms values

### Problem 3: Burst Load Failures
**Before:** 363 of 1000 requests failed with connection errors under burst load

**After:** All 1,949 requests in always_fast test completed 200 OK

**Impact:** 
- Gateway no longer CPU-saturated
- System stable under realistic peak load
- Prometheus scraping successful throughout

```

- Throughput: ~15 req/s sustained
- Per-VU capacity: 3 req/s per VU
- Latency: Minimal queuing

Heavy Stage (25 VUs, 35-70s):
- Throughput: ~20-24 req/s (not 5x more!)
- Bottleneck: GPU model inference, not VU count
- Latency: Slight queueing (p50/p95 not yet measured)

Burst Stage (50 VUs, 70-130s):
- Peak throughput: ~30 req/s (only 1.5x more than Heavy)
- Clear saturation: queues form
- Latency: Increasing tail latency
```
